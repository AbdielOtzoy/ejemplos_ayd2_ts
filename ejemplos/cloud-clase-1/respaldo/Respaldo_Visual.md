# Respaldo de la demostración Vercel

Abrir `recorrido.html` directamente en el navegador. Usa recursos locales y botones o flechas del teclado. No requiere Internet.

Contiene configuración ilustrativa, arquitectura, build, fallo v3 y comparación de versiones. Las capturas se tomaron **localmente**: v1 en Docker y v2 desde la salida estática. `vercel` es la etiqueta preparada por el build, no evidencia de despliegue remoto. La tabla de Vercel no es una captura real de su panel.

Si falla la conexión, esperar hasta dos minutos y explicar el síntoma. Continuar con el build local y el diagrama. Decir: “Podemos comprobar los archivos y el proceso local; no estamos comprobando ahora una URL publicada en Vercel”. No simular encabezados de CDN ni afirmar que un despliegue está Ready sin observarlo.

Si falla Docker, mostrar la captura v1 y continuar con el build. Si falla todo el entorno de ejecución, recorrer el respaldo y pedir al grupo anticipar resultados. Conservar la actividad de responsabilidades y consumo.

Antes de cerrar, revisar si el proyecto Vercel del docente se conservará. Si se retira, verificar su identidad y eliminar solo ese proyecto, no el repositorio ni otros proyectos. No se crearon recursos GCP para este nuevo ejemplo.
